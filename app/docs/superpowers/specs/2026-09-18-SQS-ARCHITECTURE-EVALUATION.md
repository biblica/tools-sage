# SQS (SAGE Qualification Service) architecture evaluation and locked decisions

Date: 2026-09-18.
Status: architecture evaluated against recovered Codex handover material and current SAGE source; provider-identity, qualification-authority, and provider-extensibility decisions locked by the user. Supersedes the "future functionality" deferral in [2026-09-09-NCA-SQS-INTEGRATION.md](2026-09-09-NCA-SQS-INTEGRATION.md) for the SQS service itself; NCA's own consumption of SQS confidence checks remains separately deferred and unchanged by this document.

## 1. What SQS is

SQS (SAGE Qualification Service) is a planned sibling service, package name `tools-sage-sqs`, whose one-sentence purpose (from its original design) is: centrally determine the lowest practical model + reasoning level that qualifies for a given SAGE capability (Grammar Analysis, Semantic Rewrite) against a given language profile, optimizing token cost and evidence quality, so individual SAGE hosts consume published evidence instead of repeating exhaustive local qualification tests.

Boundary: SQS builds, measures, and publishes evidence. SAGE maps sealed tasks to capabilities, checks local provider availability, consumes validated local SQS evidence, and executes locally. Prediction/pruning may reduce qualification cost but is never qualification proof.

## 3. SQS side: data/API contract (verified against source + tests, not narrative docs)

The original design docs (`docs/ARCHITECTURE.md`, `DATA_MODEL.md`, `EVALUATION_ALGORITHM.md`, `API.md`, `ADMIN.md`, `SAGE_HOST_INTEGRATION.md`, `SECURITY_AND_PRIVACY.md`, `ACCEPTANCE_CRITERIA.md`, `examples/`) referenced by the original README do not exist anywhere in the recovered material. Everything below is reconstructed from `services/sqs/src/sage_sqs/`, `services/sqs/contracts/*.schema.json`, and `services/sqs/tests/`, which is more reliable (test-backed) but narrower than the lost docs would have been.

**Bundle/publication** (`contracts/sqs-bundle-1.0.schema.json`, `sqs-bundle.schema.json` = 1.1): top-level required `schema_version, service_version, authority_id, publication_epoch, bundle_revision, generated_at, profiles, models, qualifications, bundle_sha256`; optional Ed25519 signing triad. `profiles[]`: `profile_id, display_name, tier, cluster, script, region, revision, evaluation_identity_sha256`. `models[]` (1.1): `provider_family` (free string as of 1.1, was `const:"openai"` in 1.0), `model_id, reasoning_levels, capability_rank, cost_rank, cost/mtok, capability_fingerprint, reasoning_tiers[] {native_id, ordinal, canonical_band, tier_class}, tier_mapping_revision, tier_mapping_fingerprint`. `qualifications[]` (1.1): `provider_family, model_id, model_capability_fingerprint, profile_id, profile_identity_sha256, capability(GRAMMAR_ANALYSIS|SEMANTIC_REWRITE), status(QUALIFIED|NOT_QUALIFIED), minimum_reasoning, minimum_native_reasoning, tier_mapping_fingerprint, quality_score, reliability_score, confidence, value, evidence_basis, estimated_unit_cost_usd, evaluated_at, evidence_sha256` — a schema-level conditional forces `minimum_reasoning`/`minimum_native_reasoning`/`tier_mapping_fingerprint` to `null` when `status = NOT_QUALIFIED`.

**Discovery intake** (`contracts/discovery.schema.json`, enforced by `discovery.py::validate_discovery`, confirmed by tests): payload must be *exactly* `{kind, sage_version, observed}`; extra keys rejected by an explicit prohibited-word blocklist, not schema validation alone. `kind: LANGUAGE_PROFILE` → `observed = {profile_id, language_code, script, region}`. `kind: MODEL` → `observed = {provider_family, model_id, reasoning_levels, capability_fingerprint}`. `capability_fingerprint` is a SAGE-side responsibility (a 64-hex sha256 the client must compute with the same canonicalization SQS uses internally: `{provider_family, model_id, reasoning_levels, capability_rank, cost_rank, cost/mtok}`).

**Public API** (`contracts/openapi.yaml`): `GET /health`, `GET /profiles[/{id}]`, `GET /models`, `GET /qualifications?...`, `GET /bundle` (ETag/304), `POST /discoveries`. **Known defect: `openapi.yaml` does not match the tested/enforced contract** — it uses lowercase `kind: language|model` and an extra `observed.model.execution_provider` field that the real validator and passing tests reject. Any future client must be built against `discovery.py`/`discovery.schema.json`/the tests, not `openapi.yaml`, until that file is corrected.

**Evaluation algorithm** (`evaluation/planner.py`): deterministic rule-based planner, not ML. Scores each `(model, profile, capability)` candidate against boolean triggers (new/changed model, cluster-confirmation eligibility, low-confidence existing route, cheaper-candidate-plausible) into a benefit/cost ranking; only schedules tests. `qualification.py::synthesize_qualification` writes the actual `QUALIFIED`/`NOT_QUALIFIED` verdict from an executed run. `recompute_route_values` assigns route "value" via Pareto dominance over (cost, quality, reliability, confidence), not a fixed threshold.

**Tier model**: `tier_class` (`ROUTINE`/`PREMIUM`/`OFF`/`UNUSED`) gates what's ever surfaced to SAGE — only `ROUTINE` tiers appear in bundles. A tier mapping requires explicit ADMIN approval (`admin.py::approve_tier_mapping`) before `approve_model` will accept it; this ADMIN gate is real, implemented code, not just a described process.

**Language identity as SQS assumes it**: `seed/languages/*.yml` hand-authors `profile_id` (BCP-47), a separate `identity: {iso_639_1, iso_639_3, script, region}` block, plus SQS-only `tier` (int) and `cluster` (string, e.g. `"portuguese"`) grouping fields. `evaluation_identity_sha256` hashes `{profile_id, revision, tier, cluster, iso_639_1, iso_639_3, script, region}` — `tier`/`cluster` are load-bearing identity, not incidental metadata.

## 4. SAGE side: current data structures (verified against live source, not historical snapshot)

**Language profile identity** is split across two registries today: an identity registry (`config/languages/registry.yml` + `relationships.yml`, 34 base ISO identities + 48 regional `{parent, region, name}` entries) and the grammar-profile registry (`config/schemas/language-profile-registry.schema.yml`, loaded by `registry.py`), keyed by canonical BCP-47 `namespace_key`, requiring `script` + `variants` (each variant: `file`, `role`), parsed into `LanguageProfileSpec`/`LanguageProfileVariantSpec`. 46 grammar profile directories exist under `config/profiles/grammar/`. Locale facts (digits, punctuation, date/time) layer as `.ldml` project override > namespace `locale_overrides` > bundled CLDR default (`locale_data.py::resolve_locale_facts`), each tagging its own source — an established, deliberate "derive from a bundled reference snapshot, don't hand-author duplicates" pattern (see the CLDR/locale-data follow-up in [2026-09-09-NCA-SQS-INTEGRATION.md](2026-09-09-NCA-SQS-INTEGRATION.md)). SAGE does **not** hand-author `iso_639_1`/`iso_639_3` per profile, and has **no** `tier`/`cluster` grouping concept at all today.

**Model/provider data model** is more developed than the historical SQS docs assumed. `model_service.py`, `model_policy.py`, `model_evaluation.py` implement a real, live, tested local qualification and routing system, governed by `config/model-policy.yml`: `unknown_route_status: UNASSESSED`, `accepted_operational_statuses: [RECOMMENDED, QUALIFIED]`, `provisional_routing.no_data_qualification_status: PROVISIONAL_UNQUALIFIED`, `known_negative_effect: BLOCK`, `stale_evidence_effect: BLOCK`, `recommendation_order`, per-skill `suite_sha256`. Model+reasoning identity today is `(provider="codex", model_id, reasoning_effort)`. **The only governed provider is `codex`** (ChatGPT-auth CLI); `llm_settings.py` explicitly marks direct OpenAI API keys and remote local-provider endpoints `PROHIBITED`. Evidence today is hand-seeded (`model-qualification-seeds.json`) and provider-scoped (`model_language_competency.py` keys strictly on `(provider, model, language)`).

**Failover**: none exists at the transport level for provider calls (`executors/http.py` makes one request, converts any transport error to a typed error, no retry/second endpoint) — correctly so, since there is currently only one governed provider and nothing to fail over to. The only existing retry is content-level: one retry of a provider call when a report-language check fails (`llm_tasks.py`), unrelated to availability. This is not a gap SQS integration needs to fix; it's a different concern (SAGE talking to the SQS control-plane over HTTP would be SAGE's first production network call in a governed path, and that connection needs its own failover per §5).

## 5. Gap analysis

1. **Provider identity conflict.** SQS's schema/seed data assume `provider_family = "openai"` (hardcoded in 1.0, still the only real example in 1.1). SAGE's only governed provider is `codex`. Publishing/recording qualification evidence as "openai" would misrepresent the actual governed access path in what will eventually be an audit trail.
2. **SQS is not arriving to an empty system.** SAGE's local qualification engine (`model_policy.py`/`model_evaluation.py`) is live and tested, and its vocabulary (`UNASSESSED`, `PROVISIONAL_UNQUALIFIED`) already looks designed to take an external evidence source. It should not be replaced.
3. **Language identity philosophy mismatch.** SQS wants hand-authored, redundant `iso_639_1`/`iso_639_3`/`tier`/`cluster` per profile. SAGE has since established the opposite principle: derive from bundled reference data, don't hand-author duplicates. `tier`/`cluster` are SQS-internal planner optimizations (grouping languages that can share a qualification test) and don't need SAGE to maintain them at all.
4. **Provider identity must be extensible, not a rename.** (Raised directly by the user.) As SAGE gains providers beyond `codex`, SQS and SAGE must onboard each new provider together. Two independently hardcoded provider lists (SQS's schema/seed catalog, SAGE's `llm_settings.py` governed-provider allowlist) will drift out of sync over time unless onboarding is a single, defined, shared action.
5. **Recovered source has real, unrelated defects**, found while re-verifying it in this session (§6): `pyproject.toml`'s `dev` extra is missing `jsonschema` (needed by `test_contract_schemas.py`); `runtime.py` creates its SQLite database as a **module-level import-time side effect** against hardcoded production paths (`/var/lib/sage-sqs`, `/etc/sage-sqs`), which is not portable and breaks test collection on any machine without those paths writable; no dependency in `pyproject.toml` is version-pinned, and the ambient environment already provided a newer `fastapi`/`starlette` than whatever this code was originally verified against. These are pre-existing defects in the recovered snapshot, not something this evaluation introduced.

## 6. Locked decisions

1. **Provider identity is an open, extensible catalog, not a hardcoded pair.** `codex` is registered as SQS's first non-`"openai"` provider family. Adding a provider in future must register it in both SQS's provider catalog and SAGE's governed-provider allowlist as one coordinated action (a shared provider descriptor, see plan Task 1); the two lists must never be independently maintained, and a provider present in one but not the other must fail closed rather than silently degrade.
2. **SQS is layered in as the evidence source, not a replacement.** SAGE's existing policy engine (`accepted_operational_statuses`, `provisional_routing`, `stale_evidence_effect`, receipts) stays as-is. Its evidence input moves from hand-seeded `model-qualification-seeds.json` to SQS's published bundle.
3. **Language identity fields SQS needs beyond a bare profile_id (`tier`, `cluster`, `iso_639_1`, `iso_639_3`) are derived by SQS itself** from SAGE's existing authoritative data (`relationships.yml`'s `parent` field for clustering, bundled ISO reference snapshots for `iso_639_1`/`iso_639_3`), not hand-authored per profile. SAGE is not required to add new fields to its own language-profile schema to satisfy SQS.
4. **`services/sqs/`, in this repository, is the working location** for the recovered SQS source, pending an explicit later decision to split it into a sibling repo (`biblica/tools-sage-sqs`) once it's stable enough to be worth the split. This stops the recurring pattern of the source only existing in exported zip files.
