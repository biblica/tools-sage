# NCA Simplified Numeric Check Rewrite Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace NCA's exact-span/role/per-reference-row-correspondence pipeline with a proportionate check: extract the numbers actually present in each indexed WIP verse (script where possible, LLM where not), compare them against the indexed OL/NIV expected numbers under an explicit ordered-or-unordered policy switch set before the Run, and separately report noteworthy text-critical information as a non-blocking advisory. This is a deliberate, user-directed simplification, not a bug fix — the current pipeline's complexity (exact character spans, typed referent roles, per-reference-row adjudication calls) is disproportionate to what the check needs, confirmed by this session's own findings: a real 4-verse Run took 10+ minutes across separate EXTRACTION and CORRESPONDENCE calls, one of which failed strict span-evidence validation and forced a retry.

**Architecture:** Two independent outputs per indexed verse/bridge-group, no cross-dependency: (1) a numeric PASS/FAIL from comparing WIP-extracted numbers against the indexed OL/NIV values, mode (ordered/unordered) fixed by policy before the Run starts; (2) an advisory, non-blocking noteworthy-text-critical-info note. Reuses the existing indexed-only inventory, WIP text routing, token-budget batch planning, and checkpoint/replay machinery unchanged — those are already proportionate and already correct (this session's own batch-size work already fixed the one real defect in that layer). Deletes and replaces the extraction schema/skill contract (collapsing exact-span/role/kind/qualifier/representation typing down to "list the numeric values found, in reading order"), deletes the CORRESPONDENCE model phase and `groups.py`'s per-reference-row adjudication entirely (the comparison becomes a deterministic, local operation, not a second model call), and replaces the FOOTNOTE phase with the new advisory pass. No dual-path, no migration — alpha software, clean rip-and-replace.

**Tech Stack:** Existing Python 3.10+ runtime, pytest, the existing SFM slicer/evidence-policy sizing authority, the existing `PhaseStore` checkpoint/replay layer, the existing `benchmark_nca.py` harness (extended, not replaced). No new runtime dependency.

**Prior art (read first):** [`2026-09-09-NCA-IMPLEMENTATION.md`](2026-09-09-NCA-IMPLEMENTATION.md) and its [design spec](../specs/2026-09-09-NCA-DESIGN.md) (the original exact-span/role/correspondence design this plan replaces — read it to understand *why* that complexity was originally introduced, not just to discard it uninspected); [`2026-09-10-NCA-OPTIMIZATION.md`](2026-09-10-NCA-OPTIMIZATION.md) (batching/checkpoint machinery this plan keeps); [`2026-09-28-NCA-BATCH-SIZE-OPTIMIZATION-PLAN.md`](2026-09-28-NCA-BATCH-SIZE-OPTIMIZATION-PLAN.md) (this session's batch-size fix, which stays valid and reusable under the new pipeline — if anything the new, much lighter extraction schema makes larger batches even safer, since response-token cost per verse drops sharply).

The user's directive: "this should be VERY basic compared to STC/RTC" — (1) extract verses in scope with indexed numeric data, (2) analyze WIP number content (script or LLM), (3) compare to the index (e.g. `{14, 200, 10000}` vs `{200, 14, 10000}` → PASS), (4) report noteworthy text-critical info separately. Existing local sealed Run data under the old schema is not migrated and is not expected to remain readable.**

## The one real tradeoff this plan must not paper over

Unordered set comparison cannot distinguish "200 men and 14 elders" from "14 men and 200 elders" — both produce `{14, 200}`, but the second is a real translation error (values swapped between referents). This is confirmed as the primary reason the *old* design carried per-reference-row role/span attribution at all — it wasn't incidental complexity, it was there specifically to catch this error class. The user's resolution: make comparison mode an explicit policy switch (`ORDERED` catches swaps at the cost of occasionally flagging legitimate reordering as a false positive requiring human review; `UNORDERED` never false-positives on reordering but never catches swaps either), plus OL context available to resolve ambiguity automatically before a human ever sees a false positive. This plan must implement the switch as a real, tested, both-paths-covered feature — not implement one mode and gesture at the other.

## Global constraints

- **No migration, no compatibility layer.** This is alpha software per explicit user direction: delete the old exact-span/role/correspondence pipeline outright (`extraction.py`'s exact-span validator and v1/v2 schemas, `groups.py`, `results.py`, `results_v2.py`, `models_v2.py`, the old skill contracts, their dedicated tests) rather than keeping them alongside the new one. Existing local sealed Run data under the old schema is not migrated and is not expected to remain readable — do not spend effort preserving it.
- Never supply the expected/indexed numbers to the extraction model call — extraction still sees only the WIP text, never the answer key. (Preserves the original design's own anti-leading-the-model principle; the comparison, not the extraction, is where the index gets used, and that comparison is local/deterministic, not a model call.)
- Keep OL HEB/GRK as Authority 1 and NIV as secondary evidence wherever both exist, matching every existing NCA doc/comment.
- Keep the existing indexed-only scope restriction (`build_inventory`/`candidate_group_ids`, already fixed this session) and the existing token-budget batch planning (`plan_batches`/`EvidencePolicy`, already fixed this session) unchanged — both are already correct and already reused, not rebuilt.
- The noteworthy-text-critical-info report is strictly advisory: it must never affect the numeric PASS/FAIL, and a Run with zero noteworthy items is not itself a finding.
- No CI wall-clock speed thresholds; report measured call/byte/accuracy numbers deterministically, matching every other NCA qualification this session and the original plans followed.
- `LIVE_MODEL_BENCHMARK_NOT_RUN` / `SQS: NOT_APPLIED` stays the honest default disclosure unless a live comparison is separately, explicitly initiated — do not claim speed/accuracy wins from synthetic measurement alone, especially given this rewrite's entire premise rests on real-world call-count/latency reduction.

## Task 3: Deterministic comparator (order switch + OL-context resolution)

**Files:** `numbers/compare.py` — check first whether its existing content is old-pipeline-specific (delete it if so) or already generic enough to extend in place; either way this plan's comparator logic lives there, not in a new parallel module.

- [x] Implement the core comparison: WIP-extracted values vs. `row.ol_values` (Authority 1) falling back to `row.niv_values` (secondary) when OL is absent, under a `numeric_comparison_mode` of `ORDERED` or `UNORDERED`:
  - `UNORDERED`: multiset equality (e.g. `Counter(wip_values) == Counter(expected_values)`).
  - `ORDERED`: exact sequence equality.
- [x] **Deviation from this bullet, per explicit user/coordinator direction during implementation:** "OL-context resolution" is implemented as *transparent surfacing, not automated disambiguation*. When `ORDERED` mode finds a multiset match but not an exact-sequence match, the outcome is `NEEDS_REVIEW` — never silently resolved to PASS or FAIL by a heuristic or a second hidden model call — with both orderings and the OL/NIV source text (`row.ol_text`/`row.niv_text`) attached as `review_context`, for a human reviewer to judge. The user was explicit: "Do NOT build a second hidden LLM call to auto-resolve this." This is a deliberate, directed narrowing of this bullet's original "attempt automatic disambiguation" framing, not an oversight — see `numbers/compare.py`'s module docstring and `ComparisonResult`.
- [x] Test both modes explicitly, including a real swapped-referent case, proving: `ORDERED` catches it, `UNORDERED` does not (by design, not by oversight) — mirroring the tradeoff called out in "The one real tradeoff this plan must not paper over," so the test suite enforces the documented behavior rather than merely describing it. Done: `test_compare.py::test_ordered_mode_catches_swapped_referents_as_needs_review` / `test_unordered_mode_cannot_catch_the_same_swap_by_design`. The `ORDERED` test was verified to genuinely fail without the implementation (temporarily replaced the `ORDERED`-mode branch with the `UNORDERED` multiset check, confirmed the test failed with `PASS != NEEDS_REVIEW`, then restored it and confirmed the suite passed again).
- [x] ~~Test the OL-resolution path with a genuine legitimate-reordering case... confirm it resolves to PASS~~ — superseded by the deviation above: a legitimate reordering and a real swap are *indistinguishable from multiset/sequence evidence alone* by design, so both now surface as `NEEDS_REVIEW` for human judgment rather than one being auto-resolved to PASS. No automatic-PASS heuristic was built or tested, per the explicit direction above.
