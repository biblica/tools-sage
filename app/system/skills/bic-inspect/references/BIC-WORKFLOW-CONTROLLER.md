# BIC workflow controller

BIC operates only through generated SAGE tasks and governed controller commands. The canonical order is:

```text
workspace preparation
→ INSPECT task and committed submission
→ optional human memory-review provenance
→ REWRITE task
→ material-risk detection and conditional bounded OL mitigation
→ concise challenge ledger and report
→ isolated SELF-CHECK task
→ transactional target commit
→ optional immutable publication
```

Use one bounded scope and three distinct BIC roles: SOURCE (`CONTENT_SOURCE`), DONOR (`LEXICAL_DONOR`), and TARGET (`GENERATED_TARGET`). SOURCE is sole content authority; DONOR is vocabulary evidence only; TARGET is a destination only. Routine INSPECT does not route donor Scripture text, pre-existing TARGET Scripture, or OL Scripture. Do not combine stages in one governed task context.

INSPECT proposes challenges and memory records but does not write target Scripture. A human memory-review receipt is optional provenance and does not authorize progression or promote a proposed memory record to `APPROVED_FOR_USE`. REWRITE receives only governed evidence routed by the task. SELF-CHECK receives the sealed staged candidate and material challenge ledger but no first-pass rationale.

Completion is determined by SAGE state and successful submission, not by file presence or a model statement.
