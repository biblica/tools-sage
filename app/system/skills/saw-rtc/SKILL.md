# SAW Reference Text Comparison (RTC) stage

Execute only the sealed SAGE governed task described by `task-manifest.json` and `ACT.md`. Use only routed immutable inputs; do not depend on provider workspace browsing, external file tools, or unlisted context. Return only the declared structured response. SAW is read-only for every external Scripture resource.

Enforce the `LOCAL EVIDENCE BOUNDARY` in `task-manifest.json`. Content evidence is SAGE-local only: use each routed file only according to its `evidence_class`. Do not use model recall, pretrained Scripture knowledge, external Scripture/translations/lexicons/commentary, web sources, or unstated facts as content evidence. General orthographic, morphological, grammatical, and syntactic competence may be used only to understand or express the routed evidence; it must not introduce unsupported content.

Reference Text Comparison (RTC) is one Operator operation orchestrated by SAGE as deterministic preflight/structural triage, conditional structural adjudication, a required Reference Text Comparison stage, conditional selective OL adjudication, and deterministic merge/coverage/finalization. This Skill receives exactly one model stage at a time. Obey the `rtc_stage` in the governed task; do not perform later stages early.

Stage rules:

1. `STRUCTURAL_ADJUDICATION`: review only the routed ambiguous structural candidates against WIP, REFERENCE, VRS, and permitted grammar evidence. VRS mappings and coordinate differences are report-only evidence: they never block RTC, make a review portion indivisible, or become missing-verse findings merely because numbering differs. Report a structural difference only when the bounded evidence supports it. No OL Scripture is routed or permitted.
2. `REFERENCE_TEXT_COMPARISON`: review the complete bounded WIP against the configured Reference Project and routed WIP grammar/local semantic evidence. Treat every actual multi-coordinate WIP or Reference source-text record as one indivisible verse bridge, check its coordinate mapping under structure/completeness, and compare the complete bridged text with all corresponding content under translation/meaning whether the two Projects' bridge shapes match or differ. A VRS mapping range is structural metadata, not itself a source-text bridge. Do not use OL Scripture. When `original_language.source_text_drift_adjudication` is `ENABLED`, defer every material content-bearing WIP–Reference variance whose correctness depends on the source text. Emit one bounded `ol_review_requests` entry per variance with a unique `deferred_finding_id`; never also emit that issue as a final finding. Never emit an OL request for grammar, readability, punctuation, spelling, USFM/structure, style, or ordinary consistency defects. Those remain direct RTC findings. When the policy is `PROHIBITED`, emit no `ol_review_requests`.
3. `SELECTIVE_OL_ADJUDICATION`: this automatic source-provenance adjudication handles only the inherited bounded WIP–Reference variance requests using the exact stage-reference inventory, predecessor evidence, and testament-correct Job binding: Hebrew for OT, Greek for NT. Return exactly one structured `ol_resolutions` object per request with a decision of `WIP_CLOSER_TO_SOURCE`, `REFERENCE_CLOSER_TO_SOURCE`, `BOTH_DEFENSIBLE`, or `INCONCLUSIVE`. SAGE, not the model, materializes finding evidence IDs. Do not broaden this internal adjudication into the separate detailed Original-Language Review, grammar, structure, style, consistency, or a new full RTC pass.

For every stage, semantically review every assigned primary coordinate or structural candidate and provide a concise `review_summary`. Do not construct task identity, coverage, check inventories, receipt IDs, fingerprints, or final ledgers; SAGE derives and validates those mechanically. If semantic packets are routed, treat them as local retrieval/triage evidence, never as findings by themselves. Grammar findings must cite routed rule IDs.

Return only the stage-specific semantic fields required by the supplied response schema. SAGE materializes `output/findings.json`, injects deterministic identity/coverage/receipts, validates each stage, and finalizes the composite RTC result. The final Operator outputs are an action report plus simple plain-text, copy/paste-ready issue blocks; SAGE does not create or modify Paratext Notes XML.
