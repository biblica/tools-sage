# BIC rewrite

Execute only the sealed SAGE governed task described by `task-manifest.json` and `ACT.md`. Use only the routed immutable inputs; do not depend on provider workspace browsing, external file tools, or unlisted context. Write only the outputs declared by the task.

Enforce the `LOCAL EVIDENCE BOUNDARY` in `task-manifest.json`. Content evidence is SAGE-local only: use each routed file only according to its `evidence_class`. Do not use model recall, pretrained Scripture knowledge, external Scripture/translations/lexicons/commentary, web sources, or unstated facts as content evidence. General orthographic, morphological, grammatical, and syntactic competence may be used only to understand or express the routed evidence; it must not introduce unsupported content.

Execute only a generated REWRITE task whose required INSPECT submission has been committed. Read every listed Skill reference. Apply the protected rewrite-detail rules without abbreviation. The declared SOURCE (`CONTENT_SOURCE`) is the complete and exclusive content authority. DONOR (`LEXICAL_DONOR`) is vocabulary evidence only; never infer or copy donor wording, verse sequence, syntax, propositions, participant structure, or discourse. Pre-existing TARGET Scripture is not input evidence. Use only committed memory, the governed project grammar, bounded translation challenges, and the task's conditional OL packet only when the material-risk rule opens it.

Work in this order:

1. Confirm task identity, scope, input hashes, and the committed INSPECT dependency.
2. Preserve every bounded source content unit, exact coordinate coverage, and all protected semantic markers; normalize layout markers only when the task policy permits it.
3. Apply the smallest sufficient target-language restructuring.
4. Use routed local semantic/index evidence before generating new alternatives. Compare only semantically viable verbs or constructions; preserve semantic precision before accessibility.
5. Record the five lexical-burden component judgments, but do not calculate workflow state or routing fields: Python derives burden totals, OL authorization, candidate-change state, urgency, and reporting level.
6. Record semantic risk and material trigger codes. Run one automatic bounded OL check only when the controller-authorized condition is material semantic-risk level 2 or higher with a material trigger. Do not consult OL merely because a candidate is uncommon.
7. When OL supports a better choice, update and revalidate the candidate. Risk 3 and 4 both complete automatically; high-risk records must retain concise material alternatives considered and the decisive reason each was rejected. REWRITE accepts no Operator candidate input.
8. Check every governed grammar rule against the candidate.
9. Write only:
   - `output/rewrite.usfm`
   - `output/grammar-assessment.json`
   - `output/translation-challenges.json`

Do not add, omit, harmonise, explain, modernise, resolve genuine ambiguity, or copy familiar wording merely because it appears in another translation. `grammar-assessment.json` must cover every routed grammar rule and bind to the candidate output hash. `translation-challenges.json` must retain the canonical machine record while listing only material urgency 2–4 challenges individually, consolidating repeated causes, and aggregating lower-level or automatically resolved matters. It must record lexical-burden components, material risk triggers, any bounded OL evidence actually used, before/after risk, and concise rejected alternatives for high-risk choices. Python derives burden totals, candidate-change state, urgency, and report routing. Linguistic uncertainty elevates the report; it does not block completion of the current REWRITE operation.

This is Pass 1 only. Do not perform SELF-CHECK or expose first-pass rationale to the later pass. Submit with the exact command in `ACT.md`.
